# Sentinel SOC v4

Hybrid honeypot-powered Security Operations Center. Sensors stay local (SSH/HTTP/FTP/Telnet honeypots); the product layer is a real analyst workflow: **deduped alerts, campaign correlation, MITRE ATT&CK, cases/SLAs, playbooks, containment with audit, and MTTA/MTTR metrics**.

## Problems this solves

| SOC pain | How Sentinel v4 addresses it |
|---|---|
| Alert fatigue | Fingerprint alerts (`ip + threat + hour`) so 200 probes → 1 alert with `event_count` |
| No ownership | Assignable alerts/cases with local analyst profiles |
| Slow triage | Keyboard shortcuts (`a` ack, `i` investigate, `e` escalate, `r` resolve, `f` FP) |
| Silent auto-block | Containment via playbooks + immutable audit log |
| Lying KPIs | `blocked` = active blocklist rows, not “high severity count” |
| Noise | False-positive → suppression rules auto-quiet matching fingerprints |
| Blind spots | Multi-port /24 campaign correlation + Investigate workspace |
| No proof of process | Cases with SLA clocks, notes, close reasons, metrics |

## Architecture

```
Honeypots → enrich (GeoIP + intel tags) → risk + MITRE
         → fingerprint alert → campaign correlate
         → SSE to UI → triage / cases / playbooks → blocklist + audit
```

## What is real and what is simulated

This is a portfolio SOC, and it says so in the product rather than in the README only.

**Real:** the four honeypots are genuine asyncio TCP listeners with service
banners — anything that connects to them is logged for real. Detection,
deduplication, campaign correlation, the alert state machine, cases and SLAs,
audit logging, and MTTA/MTTR are all computed from stored data.

**Simulated:** an ambient attack generator (`live_attacks.py`, on by default)
injects traffic so the dashboard is never empty. GeoIP for 26 demo IPs and the
Tor/scanner/VPN intel tags come from curated local tables, not live feeds.

Every event and alert carries a `source` column:

| Value | Meaning | UI badge |
|---|---|---|
| `sensor` | A honeypot actually received this | `REAL` |
| `simulator` | Generated by the built-in demo generator | `SIM` |
| `mixed` | An alert fed by both | `MIX` |
| `unlabelled` | Predates provenance tracking; origin unknown | `—` |

Filter with `GET /api/events?source=sensor`, or turn the generator off entirely
with `SENTINEL_LIVE_ATTACKS=0`.

**Stopping the simulator at runtime.** The demo banner carries a
**Stop simulation** button — no restart needed. Pausing halts generation and
clears the ticker and toasts so the screen quietens down; honeypot sensors keep
ingesting throughout. The toggle is audited and broadcast over SSE, so other
open tabs stay in sync.

```bash
curl -X POST localhost:8000/api/simulator \
  -H "X-API-Key: $SENTINEL_API_KEY" -H 'Content-Type: application/json' \
  -d '{"enabled": false}'
```

## Containment honesty

Programming the OS firewall needs elevated privileges. When Sentinel cannot do
it, the block is still recorded — but it is **never reported as enforced**.
`GET /api/health` exposes the real capability, every blocklist row carries an
`enforced` flag, and the UI shows a warning banner plus a per-row
`firewall` / `recorded only` chip. Run the API elevated (or the container with
`NET_ADMIN`) for real enforcement.

## Deploy

```bash
cp .env.example .env       # set SENTINEL_API_KEY
docker compose up --build  # dashboard :5173, API :8000
```

Before exposing this publicly, understand these limits:

- **The API key ships inside the JavaScript bundle.** Vite inlines it at build
  time, so anyone who loads the dashboard can read it. It deters casual access;
  it is not authentication. The SSE endpoint also takes it as a query parameter,
  which proxies and browser history will log.
- **Run exactly one worker.** SSE subscribers live in process memory, so a
  second worker silently breaks real-time updates. Scaling out needs Redis
  pub/sub first.
- **GeoIP is the ingest bottleneck.** Addresses outside the local atlas hit
  `ip-api.com`, which allows 45 requests/minute over plaintext HTTP. Measured
  under load: known IPs ingest 40 probes in 0.11s at 20ms API latency; unknown
  IPs drop ~32% of events and push API latency to ~3.8s. A public-facing sensor
  needs a local MaxMind database instead.
- **SQLite has no retention policy.** The events table grows without bound.

## Quick start

### Backend

```bash
cd backend
pip install -r requirements.txt
python seed_data.py          # realistic 7-day SOC history
```

**Windows (recommended):** from `backend`, run `.\start.ps1` or double-click `start.bat`.  
This frees ports 8000/2222/8080/2121/2323 if a previous instance is stuck, then starts the API.

**Manual start** (must be inside the `backend` folder — not the repo root):

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```

Common mistakes:
- Running from the project root → `Could not import module "main"` (cd into `backend` first)
- `--port 8000.` with a trailing period → invalid integer
- Starting a second copy while one is already running → WinError 10048 (use `start.ps1` or kill the old PID)

API docs: http://localhost:8000/api/docs  
Default API key: `sentinel-dev-key` (header `X-API-Key`)  
Acting analyst: header `X-Analyst` (`alice` | `bob` | `soc-lead`)

### Frontend

```bash
cd frontend
npm install
npm run dev                  # http://localhost:5173
```

### Live demo traffic

With the API running:

```bash
cd backend
python test_traffic.py
```

## Playbooks

| ID | Effect |
|---|---|
| `contain_ip` | Firewall block + blocklist + audit |
| `escalate_critical` | Escalate alert, open case → `soc-lead`, 30m SLA |
| `recon_burst_response` | Contain IP, escalate open alerts, open case |
| `false_positive_cleanup` | Mark FP + 24h fingerprint suppression |
| `auto_contain_repeat_offender` | System: ≥10 hits → contain (12h) |

## Out of scope (by design)

SSO/SAML, multi-tenant orgs, Kafka, live MISP/VirusTotal keys, endpoint agents, full Sigma engine. Intel tags use seeded lists with a pluggable enrichment path.

## Path to a production sensor

The gap between this and something you would run for real:

1. Replace the `ip-api.com` call in `geoip.py` with a bundled MaxMind GeoLite2
   database, removing the network hop from the ingest path.
2. Swap SQLite for Postgres and move SSE fan-out to Redis pub/sub so the API
   can run more than one worker.
3. Replace the shared API key with per-user authentication; the `X-Analyst`
   header is currently self-asserted.
4. Add a retention job to age out events.
5. Point the honeypots at real ports (22/80/21/23) on a host you are willing to
   expose, and set `SENTINEL_LIVE_ATTACKS=0`.
